# نظام تحضير أعضاء هيئة التدريس — جامعة القصيم

نظام ويب متكامل وفعّال (وليس مجرد واجهات شكلية) لتسجيل حضور أعضاء هيئة
التدريس للمحاضرات، مع التحقق التلقائي من الوقت، الموقع الجغرافي (GPS)،
وجدول المحاضرات المسجَّل.

---

## 1. البنية المعمارية (Architecture)

```
┌──────────────────────┐        HTTPS/JSON        ┌──────────────────────┐
│   Frontend (React)   │  ───────────────────────▶ │  Backend (Express)   │
│   Vite + RTL + JWT    │ ◀─────────────────────── │  JWT + bcrypt + RBAC  │
└──────────────────────┘                            └──────────┬───────────┘
                                                                 │
                                                                 ▼
                                                     ┌──────────────────────┐
                                                     │  SQLite Database      │
                                                     │  (better-sqlite3)     │
                                                     └──────────────────────┘
```

- **Frontend:** React (Vite)، RTL كامل، بدون أي منطق أمني على العميل —
  حالة زر "تحضير" وحساب المسافة الجغرافية تُحسب في السيرفر دائمًا.
- **Backend:** Node.js/Express، مسؤول عن كل التحقق (RBAC، الوقت، GPS).
- **Database:** SQLite عبر الوحدة المدمجة `node:sqlite` (بدون أي حزمة
  native خارجية تحتاج تجميعًا/Python/Visual Studio) — تعمل مباشرة على
  أي جهاز فيه Node.js 22.5 أو أحدث. نفس الـ Schema قابل للنقل مباشرة إلى
  PostgreSQL أو MySQL عند التوسع.
- **firestore.rules:** ملف قواعد أمان جاهز في حال رغبتم مستقبلًا بترحيل
  قاعدة البيانات إلى Firebase Firestore بدلًا من SQLite.

---

## 2. Database Schema

راجع `backend/db/schema.sql` للتفاصيل الكاملة. الجداول الأساسية:

| الجدول | الوصف |
|---|---|
| `departments` | الأقسام الأكاديمية |
| `semesters` | الفصول الدراسية (فصل واحد فقط "فعّال" في كل وقت) |
| `users` | كل المستخدمين (admin / faculty / monitor) بدور واحد لكل صف |
| `courses` | المقررات الدراسية |
| `schedules` | جدول محاضرات كل عضو (يوم، وقت بداية/نهاية، شعبة) |
| `attendance` | سجل الحضور الفعلي لكل محاضرة/تاريخ (GPS، مسافة، وقت) |
| `excuses` | أعذار الغياب المرتبطة بسجل حضور |
| `university_location` | إحداثيات الجامعة والنطاق المسموح (Radius) |

## 3. آلية عمل التحضير (Flow)

1. العضو يفتح Dashboard فتظهر له محاضرات اليوم فقط (بحسب جدوله والفصل
   الدراسي الفعّال حاليًا).
2. زر "تحضير" يُفعَّل تلقائيًا فقط ضمن نافذة (بداية المحاضرة − 15 دقيقة)
   حتى (نهاية المحاضرة + 15 دقيقة) — **يُحسب هذا في السيرفر بالكامل**
   اعتمادًا على ساعة الخادم، وليس ساعة جهاز المستخدم.
3. عند الضغط على "تحضير"، يطلب المتصفح صلاحية GPS، ثم يُرسل الإحداثيات
   إلى `POST /api/faculty/attendance/check-in`.
4. السيرفر يتحقق بالترتيب من:
   - أن المحاضرة ضمن جدول العضو فعلًا.
   - أن اليوم مطابق ليوم المحاضرة.
   - أن الوقت الحالي ضمن نافذة التحضير.
   - أنه لم يُسجَّل حضور مسبق لنفس المحاضرة/التاريخ.
   - أن المسافة (Haversine) بين موقع العضو وموقع الجامعة المخزَّن في
     قاعدة البيانات أقل من أو تساوي النطاق المسموح.
5. عند نجاح كل الشروط يُسجَّل الحضور مع الوقت، الإحداثيات، والمسافة.

## 4. تشغيل المشروع محليًا

### المتطلبات
- Node.js 22.5 أو أحدث (لدعم وحدة `node:sqlite` المدمجة). أثناء التشغيل
  قد تظهر رسالة تحذير عادية مثل:
  `ExperimentalWarning: SQLite is an experimental feature` — هذا طبيعي
  ولا يؤثر على عمل النظام، ويمكن تجاهله.

### تشغيل الـ Backend

```bash
cd backend
npm install
npm run seed     # ينشئ بيانات ابتدائية (أقسام، مستخدمين تجريبيين، جدول)
npm start        # يشغّل API على http://localhost:4000
```

بعد `npm run seed` ستحصل على الحسابات التالية:

| الدور | الرقم الوظيفي | كلمة المرور |
|---|---|---|
| Admin | `ADMIN001` | `Admin@12345` |
| Monitor (قسم علوم الحاسب) | `MON001` | يحتاج أول تسجيل دخول |
| Faculty | `1001` أو `1002` | يحتاج أول تسجيل دخول |

> **مهم:** بعد أول تشغيل، ادخل إلى لوحة الـ Admin وحدّث **موقع الجامعة
> الفعلي** من صفحة "موقع الجامعة" — الإحداثيات الافتراضية وهمية.

### تشغيل الـ Frontend

```bash
cd frontend
npm install
npm run dev       # يشغّل الواجهة على http://localhost:5173
```

الواجهة تتصل تلقائيًا بالـ API عبر proxy مُعدّ مسبقًا في `vite.config.js`.

### البناء للإنتاج

```bash
cd frontend && npm run build   # ينتج مجلد dist/ جاهز للنشر على أي استضافة ثابتة
cd backend && npm start        # يُشغَّل عادة خلف Nginx/PM2 في الإنتاج
```

## 5. رفع البيانات (CSV)

> 💡 **نماذج جاهزة:** يوجد مجلد `templates/` في هذا المشروع يحتوي على ملفي
> CSV جاهزين بالأعمدة الصحيحة والترميز الصحيح (UTF-8 مع BOM حتى يفتحهما
> Excel بشكل سليم بالعربية) — افتحهما مباشرة في Excel واستبدل الصفوف
> التجريبية ببياناتك الفعلية.

> ✅ **تلقائي:** النظام يكتشف تلقائيًا ترميز الملف (UTF-8 أو Windows-1256
> العربي الشائع عند حفظ Excel لملف CSV على ويندوز) والفاصل المستخدم بين
> الأعمدة (فاصلة `,` أو فاصلة منقوطة `;` الشائعة في النسخ العربية من
> Excel) — يمكنك رفع أي من الشكلين مباشرة بدون تعديل الملف يدويًا.

### أسماء الأعمدة المقبولة (عربي أو إنجليزي)
| المعنى | الأسماء المقبولة |
|---|---|
| الرقم الوظيفي | `employee_number` أو `الرقم الوظيفي` |
| الاسم الكامل | `full_name` أو `الاسم` |
| القسم | `department_name` أو `القسم` أو `التخصص` |

### استيراد أعضاء هيئة التدريس
من لوحة Admin ← "المستخدمون" ← رفع ملف CSV بالأعمدة:
```
الرقم الوظيفي,الاسم,القسم
1003,د. خالد المطيري,علوم الحاسب
```
(أو بالأعمدة الإنجليزية: `employee_number,full_name,department_name`)

### استيراد الجداول
من لوحة Admin ← "الجداول والمقررات" ← رفع ملف CSV بالأعمدة:
```
الرقم الوظيفي,اسم المقرر,رمز المقرر,اليوم,وقت البداية,وقت النهاية,الشعبة
1003,هياكل البيانات,CS210,الأحد,09:00,10:00,1
```
(أو بالأعمدة الإنجليزية: `employee_number,course_name,course_code,day,start_time,end_time,section`)
(يجب تفعيل فصل دراسي أولًا من صفحة "الفصول الدراسية").

### رفع الجدول عبر PDF (بديل اختياري)
تدعم صفحة "الجداول والمقررات" أيضًا رفع ملف PDF بدلاً من CSV، بشرط أن
تكون كل محاضرة في سطر مستقل داخل الملف، والحقول مفصولة بالرمز `|`
بهذا الترتيب:
```
الرقم_الوظيفي|اسم_المقرر|رمز_المقرر|اليوم|وقت_البداية|وقت_النهاية|الشعبة
1003|هياكل البيانات|CS210|الأحد|09:00|10:00|1
```
⚠️ **ملاحظة:** استخراج البيانات من PDF أقل موثوقية من CSV لأن الملف نص
وليس جدول بيانات حقيقي. **الطريقة الموصى بها هي CSV** لأنها مضمونة
100%، واستخدم PDF فقط إذا كانت هذه هي الصيغة الوحيدة المتوفرة لديك.

## 6. الأمان المطبَّق

- كلمات المرور تُخزَّن بتقنية bcrypt (hash)، وليس نصًا واضحًا.
- كل التحقق من الصلاحيات (RBAC) يتم في الـ Backend عبر middleware مخصص
  (`middleware/auth.js`)، وليس فقط في الواجهة.
- كل مسارات Admin/Faculty/Monitor محمية بـ JWT + دور محدد.
- مراقب القسم مقيَّد فعليًا بـ `department_id` الخاص به في كل استعلام.
- منع التحضير خارج نطاق الجامعة، خارج الوقت المسموح، أو لمحاضرة ليست
  ضمن جدول العضو، أو تكرار تسجيل حضور لنفس المحاضرة — كل ذلك مفروض من
  السيرفر (انظر `routes/faculty.js`).
- `firestore.rules` مرفق كخيار بديل إن تم الترحيل إلى Firebase مستقبلًا.

## 8. التوسعات المستقبلية المقترحة

- إرسال بريد إلكتروني فعلي عند إعادة تعيين كلمة المرور (يتطلب SMTP).
- رفع مرفقات للأعذار (health/family/other) — الحقل جاهز في الـ Schema.
- تصدير PDF مباشر للتقارير (حاليًا CSV يفتح مباشرة في Excel، ويمكن
  إضافة توليد PDF عبر مكتبة مثل `pdfkit` بسهولة على نفس نمط `/reports`).
- صفحة موافقة/رفض الأعذار من لوحة الـ Admin (الجدول والحالة `pending`
  جاهزان في قاعدة البيانات، تحتاج فقط route وواجهة إضافية).
